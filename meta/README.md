# Meta Generation System

Pharos의 메타데이터 생성 및 관리 시스템입니다. 사이트 모드(SITE_MODE)별로 서로 다른 extension, 메뉴 구성, UI 설정을 지원합니다.

## 📁 디렉토리 구조

```
meta/
├── README.md              # 이 문서
├── configs/               # 사이트 모드별 설정 파일
│   ├── default.json       # 기본 Pharos 모드
│   ├── demo.json          # Demo 메뉴 활성화 모드
│   └── catv.json          # CATV 전용 모드
├── scripts/               # 메타데이터 생성 스크립트
│   ├── generate-metadata.ts  # 프론트엔드 메타데이터 생성
│   └── generate-metadata.go  # 백엔드 import 생성
└── generated/             # 생성된 파일들 (자동생성, .gitignore 적용)
    └── frontend/
        ├── extension-loader.ts   # Extension 동적 로딩
        ├── vite-extensions.json  # Vite alias/exclude 설정
        └── menu-order.ts         # 메뉴 순서 및 구조
```

## 🚀 사용법

### 메타데이터 생성

```bash
# 특정 사이트 모드로 생성
SITE_MODE=catv pnpm exec tsx meta/scripts/generate-metadata.ts

# 개발 서버 실행 시 자동 생성
SITE_MODE=catv pnpm run dev

# 프로덕션 빌드 시 자동 생성
SITE_MODE=catv pnpm run build
```

### 사용 가능한 SITE_MODE

- `default` - 기본 Pharos 사이트
- `demo` - default와 동일하나 Demo 메뉴 활성화
- `catv` - CATV 관리 시스템

## ⚙️ 설정 파일 (meta/configs/{mode}.json)

사이트 모드별로 독립된 파일로 관리합니다:

```json
{
  "title": "CATV",
  "description": "CATV Management System",
  "icon": "catv/images/favicon.svg",
  "login-extension": "catv/login",
  "extensions": [
    "catv/business",
    "dashboard/datasources/clickhouse",
    "demo"
  ],
  "menu-order": [
    {
      "label": "Dashboard",
      "items": [
        {
          "extension": "core",
          "name": "starred-tree",
          "display_name": "Favorites",
          "flat": true
        }
      ]
    },
    {
      "label": "CATV",
      "separator": true,
      "items": [
        {
          "extension": "catv",
          "name": "stb-control",
          "display_name": "STB Control"
        }
      ]
    }
  ]
}
```

### 설정 필드 설명

#### 기본 설정
- `title`: 브라우저 타이틀
- `description`: 사이트 설명 (메타데이터용)
- `icon`: 파비콘 경로 (`extensions/{root}/images/` 기준, `generate-metadata` 실행 시 `public/images/`로 복사됨)

#### Extension 설정
- `login-extension`: 로그인 페이지 extension 경로
  - 예: `"catv/login"` → `extensions/catv/login/`
- `extensions`: 포함할 extension 목록 (디렉토리 경로)
  - 예: `"catv/business"` → `extensions/catv/business/`

> **로고**는 JSON 설정이 아닌 코드로 등록합니다. 각 login extension의 `index.ts`에서 `registerSidebarLogo(LogoComponent)`를 호출하세요.

#### 메뉴 설정 (menu-order)
계층적 메뉴 구조를 정의합니다.

**MenuOrderGroup 구조**:
```typescript
{
  "label": "그룹 이름",        // 선택사항: 그룹 레이블
  "separator": true,          // 선택사항: 구분선 표시
  "hidden": true,             // 선택사항: 숨김 처리
  "items": [                  // 필수: 메뉴 아이템 배열
    {
      "extension": "core",    // 필수: extension ID
      "name": "dashboard",    // 필수: 메뉴 ID
      "display_name": "대시보드", // 선택사항: 표시 이름
      "hidden": false,        // 선택사항: 숨김 여부
      "flat": false,          // 선택사항: 하위 메뉴 펼치기
      "items": []             // 선택사항: 하위 메뉴
    }
  ]
}
```

## 📤 생성되는 파일들

### 1. extension-loader.ts

Extension 동적 로딩을 위한 import 문들을 생성합니다.

```typescript
/**
 * Extension Loader (AUTO-GENERATED)
 * Generated by: pnpm generate:metadata
 */

// Extension: catv/business
import '@pharos/extension-catv-business';
// Extension: catv/login
import '@pharos/extension-catv-login';
```

**자동 package.json 수정**:
- 규칙: `extensions/{path}` → `@pharos/extension-{path-with-dashes}`
- package.json의 name이 규칙과 다르면 **자동으로 수정**

### 2. vite-extensions.json

Vite의 alias 및 optimizeDeps 설정에 사용됩니다. `vite.config.ts`가 이 파일을 읽어 동적으로 구성합니다.

```json
{
  "extensions": [
    {
      "name": "@pharos/extension-catv-business",
      "path": "../../extensions/catv/business/frontend/src"
    }
  ]
}
```

`vite.config.ts`에서 별도 수정 없이 자동으로 반영됩니다.

### 3. menu-order.ts

메뉴 순서 및 구조를 export합니다.

```typescript
export const MENU_ORDER: MenuOrderGroup[] = [
  // ... configs/{mode}.json의 menu-order 내용
];
```

**Validation**:
- 모든 아이템에 `extension`, `name` 필드 필수
- 중복 키(`{extension}:{name}`) 감지 및 에러

### 4. .env.local + 이미지 복사

`core/frontend/.env.local` 파일 생성:
```env
VITE_TITLE=CATV
VITE_ICON=/ui/images/catv/images/favicon.svg
```

파비콘 이미지를 `extensions/{root}/images/` → `core/frontend/public/images/{root}/images/`로 복사합니다.

## 🏗️ 빌드 프로세스

### 프론트엔드 빌드

`core/frontend/package.json`:
```json
{
  "scripts": {
    "dev": "tsx ../../meta/scripts/generate-metadata.ts && vite",
    "build": "tsx ../../meta/scripts/generate-metadata.ts && vite build"
  }
}
```

**실행 순서**:
1. `generate-metadata.ts` 실행
2. Extension package.json 자동 수정
3. `vite-extensions.json` 생성
4. 파비콘 이미지 복사
5. Vite 빌드/개발서버 실행

### 백엔드 빌드

```bash
go run meta/scripts/generate-metadata.go
```

`configs/{mode}.json`의 `extensions` 목록을 읽어 `core/cmd/pharos/import_extensions.go`를 자동 생성합니다.

## 📋 Extension 추가 워크플로우

### 1. Extension 디렉토리 생성
```bash
mkdir -p extensions/my-category/my-extension/frontend/src
```

### 2. package.json 작성
```json
{
  "name": "any-name-will-be-auto-fixed",
  "version": "1.0.0",
  "private": true,
  "main": "src/index.ts"
}
```

### 3. configs/{mode}.json에 등록
```json
{
  "extensions": ["my-category/my-extension"],
  "menu-order": [
    {
      "items": [
        {
          "extension": "my-extension",
          "name": "my-menu-id",
          "display_name": "My Menu"
        }
      ]
    }
  ]
}
```

### 4. 메타데이터 생성
```bash
SITE_MODE=mymode pnpm exec tsx meta/scripts/generate-metadata.ts
```

자세한 내용은 [`extensions/README.md`](../extensions/README.md)를 참고하세요.

## ⚠️ 주의사항

### ✅ 해야 할 것
1. **SITE_MODE 설정**: 빌드/개발 전 반드시 환경변수 설정
2. **configs/{mode}.json 업데이트**: 새 extension 추가 시 등록
3. **메타데이터 재생성**: 설정 변경 후 스크립트 실행

### ❌ 하지 말아야 할 것
1. **generated/ 폴더 직접 편집**: 자동 생성되므로 덮어씌워짐
2. **extension package.json name 수동 관리**: 자동으로 규칙에 맞게 수정됨
3. **vite.config.ts의 extension alias 수동 편집**: `vite-extensions.json`으로 자동 관리됨

## 🐛 트러블슈팅

### SITE_MODE에 해당하는 config 파일이 없음
```
✗ Error: No config file found for SITE_MODE "mymode"
  Expected: meta/configs/mymode.json
```
**해결**: `meta/configs/mymode.json` 파일을 생성하세요.

### Extension이 로드되지 않음
1. `configs/{mode}.json`의 `extensions` 배열에 경로가 있는지 확인
2. 메타데이터 생성을 실행했는지 확인
3. `meta/generated/frontend/extension-loader.ts`에 import가 있는지 확인
4. 개발 서버를 재시작했는지 확인

### 중복 메뉴 키 에러
```
✗ Error: Duplicate menu keys in menu-order: catv:stb-control
```
**해결**: `menu-order`에서 같은 `{extension}:{name}` 조합이 2번 이상 나오지 않도록 수정

1. 개요
--------------------------------------------------------------------------------

Kubernetes 클러스터 모니터링 전용 홈 화면.
기존 대시보드 시스템에 의존하지 않고 Prometheus에 직접 쿼리하는 독립 페이지.

주요 기능:
  - Cluster Summary (CPU/MEM 전체 사용률)
  - Node Topology (노드별 Pod 상태 시각화)
  - Pod 상세 패널 (클릭 시 CPU/MEM/Storage/Network 표시)
  - Active Alarms (Alerta 알람 목록, open 상태만)
  - Namespace/Node 멀티셀렉트 필터 (동적 조회)
  - Refresh 주기 선택 (Off / 10s / 30s / 1m / 5m)

--------------------------------------------------------------------------------
2. 아키텍처
--------------------------------------------------------------------------------

[React 프론트엔드]
  → GET  /home-upm           : datasource 이름 조회 (백엔드 config)
  → POST /plugins/ds/query  : Prometheus PromQL 쿼리 (배치)
  → GET  /alarm/alerts      : Alerta 알람 목록

[백엔드 Go]
  → GET /home-upm            : master_config.toml [home_upm] 섹션 반환
  → POST /plugins/ds/query  : datasource proxy (기존 엔드포인트 재사용)

Prometheus datasource: prometheus-metric
  address: http://10.255.254.22:30232

4. PromQL 쿼리 목록
--------------------------------------------------------------------------------

[Pod 데이터 - 배치 쿼리 9+3개]
  podInfo      : kube_pod_info{namespace=~"...", node=~"..."}
  podPhase     : kube_pod_status_phase{namespace=~"..."}
  podRestarts  : sum by (pod) (kube_pod_container_status_restarts_total)
  cpuUsage     : node_namespace_pod_container:container_cpu_usage / kube_pod_container_resource_limits(cpu)
  memUsage     : container_memory_working_set_bytes / kube_pod_container_resource_limits(memory)
  clusterCpuReq: 전체 CPU requests 대비 사용률
  clusterCpuLim: 전체 CPU limits 대비 사용률
  clusterMemReq: 전체 Memory requests 대비 사용률
  clusterMemLim: 전체 Memory limits 대비 사용률
  storageUsage : kubelet_volume_stats_used_bytes / kubelet_volume_stats_capacity_bytes
  networkRx    : rate(container_network_receive_bytes_total[5m])
  networkTx    : rate(container_network_transmit_bytes_total[5m])

[클러스터 메타 - 별도 쿼리 (staleTime 5분)]
  namespaces   : group by (namespace) (kube_namespace_status_phase{phase="Active"})
  nodes        : group by (node) (kube_node_info)

--------------------------------------------------------------------------------
5. Pod 상태 판정 기준
--------------------------------------------------------------------------------

  error   : phase=Failed/Unknown, 재시작>=5회, CPU>=95%, MEM>=95%
  warning : phase=Pending, 재시작>=3회, CPU>=80%, MEM>=80%
  normal  : 그 외

Node 상태:
  error   : pod 중 error 존재 or CPU>=90% or MEM>=90%
  warning : pod 중 warning 존재 or CPU>=70% or MEM>=70%
  normal  : 그 외

7. 알려진 이슈 / 확인 필요 사항
--------------------------------------------------------------------------------

- CPU/MEM 사용률이 0%로 나올 경우
  → kube-prometheus-stack recording rule 존재 여부 확인
     node_namespace_pod_container:container_cpu_usage_seconds_total:sum_rate5m
     cluster:namespace:pod_cpu:active:kube_pod_container_resource_limits
     cluster:namespace:pod_memory:active:kube_pod_container_resource_limits

- Storage 사용률이 0%로 나올 경우
  → kubelet_volume_stats_used_bytes 메트릭 존재 여부 확인
  → volume이 없는 pod는 정상적으로 0% 표시됨

- Network 수치가 0으로 나올 경우
  → container_network_receive/transmit_bytes_total 메트릭 확인

- cluster 필터 기본값: "" (빈 문자열 = 전체)
 → 특정 cluster만 보려면 URL 파라미터: ?cluster=upm-ems

9. URL 원복 방법
--------------------------------------------------------------------------------

home-upm 화면 적용 후 URL 이동이 꼬이거나 기존 홈 화면으로 되돌려야 할 경우,
아래 파일들의 `/home-upm` 변경분을 기존 `/home` 기준으로 원복한다.

[프론트엔드 라우트]
  core/frontend/src/App.tsx
    - 현재:
      const HomeUPMPage = React.lazy(() => import('@/routes/home-upm/page'));
      <Route path="/" element={<Navigate to="/home-upm" replace />} />
      <Route path="/home" element={<Navigate to="/home-upm" replace />} />
      <Route path="/home-upm" element={<HomeUPMPage />} />

    - 원복:
      const HomePage = React.lazy(() => import('@/routes/home/page'));
      const HomeUPMPage = React.lazy(() => import('@/routes/home-upm/page')); // 필요 시 유지
      <Route path="/" element={<Navigate to="/home" replace />} />
      <Route path="/home" element={<HomePage />} />
      <Route path="/home-upm" element={<HomeUPMPage />} /> // 필요 시 유지 또는 제거

    - 설명:
      BrowserRouter basename="/ui"가 적용되어 있으므로 앱 내부 경로 `/home`은
      실제 브라우저 URL에서 `/ui/home`으로 보인다.

[로그인 완료 후 이동]
  core/frontend/src/routes/login/page.tsx
    - 현재:
      navigate('/home-upm');

    - 원복:
      navigate('/home');

    - 위치:
      로그인 직후 사용자 정보를 가져온 뒤 이동하는 부분 1곳,
      password change 같은 required action 완료 후 이동하는 부분 1곳.

[AuthProvider redirectTo]
  core/frontend/src/providers/auth-provider/index.ts
    - 현재:
      return { success: true, redirectTo: '/home-upm' };

    - 원복:
      return { success: true, redirectTo: '/home' };

    - 설명:
      다른 로그인 플로우나 data-provider 기반 로그인 흐름에서 redirectTo를 사용할 수 있으므로
      login/page.tsx와 같이 맞춰두는 것이 좋다.

[인덱스 페이지 리다이렉트]
  core/frontend/src/routes/page.tsx
    - 현재:
      <Navigate to="/home-upm" replace />

    - 원복:
      <Navigate to="/home" replace />

[사이드바 로고 링크]
  core/frontend/src/features/menu/components/AppSidebar.tsx
    - 현재:
      <Link to="/home-upm" ...>

    - 원복:
      <Link to="/home" ...>

[점검 명령]
  - home-upm 이동 경로 확인:
      rg -n "'/home-upm'|\"/home-upm\"|home-upm" core/frontend/src --glob "*.ts" --glob "*.tsx"

  - 기존 home 이동 경로 확인:
      rg -n "'/home'|\"/home\"|to=\"/home\"|path=\"/home\"" core/frontend/src --glob "*.ts" --glob "*.tsx"

[권장 원복 순서]
  1) core/frontend/src/App.tsx에서 `/home` 라우트를 기존 HomePage로 복구한다.
  2) core/frontend/src/routes/login/page.tsx의 navigate 값을 `/home`으로 복구한다.
  3) core/frontend/src/providers/auth-provider/index.ts의 redirectTo 값을 `/home`으로 복구한다.
  4) core/frontend/src/routes/page.tsx와 AppSidebar.tsx 링크를 `/home`으로 복구한다.
  5) `/ui/`, `/ui/login` 로그인 후 이동, `/ui/home`, `/ui/home-upm` 직접 접근을 확인한다.

주의:
  - `/home-upm` 화면 자체를 유지하면서 기본 진입점만 원복할 수도 있다.
    이 경우 App.tsx의 `<Route path="/home-upm" element={<HomeUPMPage />} />`는 남겨둔다.
  - `/home-upm` 화면을 완전히 제거하려면 routes/home-upm, home-dashboard hook/API,
    백엔드 `/home-upm` API, [home_upm] 설정까지 함께 정리해야 한다.

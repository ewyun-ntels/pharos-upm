--------------------------------------------------------------------------------
1. 개요
--------------------------------------------------------------------------------

Kubernetes 클러스터 모니터링 전용 홈 화면.
기존 대시보드 시스템에 의존하지 않고 Prometheus에 직접 쿼리하는 독립 페이지.

주요 기능:
  - Cluster Summary (CPU/MEM 전체 사용률)
  - Node Topology (노드별 Pod 상태 시각화)
  - Pod 상세 패널 (클릭 시 CPU/MEM/Storage/Network 표시)
  - Active Alarms (Alerta 알람 목록, open 상태만)
  - Namespace/Node 멀티셀렉트 필터 (동적 조회)
  - Refresh 주기 선택 (Off / 10s / 30s / 1m / 5m)

--------------------------------------------------------------------------------
2. 아키텍처
--------------------------------------------------------------------------------

[React 프론트엔드]
  → GET  /home-upm           : datasource 이름 조회 (백엔드 config)
  → POST /plugins/ds/query  : Prometheus PromQL 쿼리 (배치)
  → GET  /alarm/alerts      : Alerta 알람 목록

  → POST /plugins/ds/query  : datasource proxy (기존 엔드포인트 재사용)

Prometheus datasource: prometheus-metric
  address: http://10.255.254.22:30232

4. PromQL 쿼리 목록
--------------------------------------------------------------------------------

[Pod 데이터 - 배치 쿼리 9+3개]
  podInfo      : kube_pod_info{namespace=~"...", node=~"..."}
  podPhase     : kube_pod_status_phase{namespace=~"..."}
  podRestarts  : sum by (pod) (kube_pod_container_status_restarts_total)
  cpuUsage     : node_namespace_pod_container:container_cpu_usage / kube_pod_container_resource_limits(cpu)
  memUsage     : container_memory_working_set_bytes / kube_pod_container_resource_limits(memory)
  clusterCpuReq: 전체 CPU requests 대비 사용률
  clusterCpuLim: 전체 CPU limits 대비 사용률
  clusterMemReq: 전체 Memory requests 대비 사용률
  clusterMemLim: 전체 Memory limits 대비 사용률
  storageUsage : kubelet_volume_stats_used_bytes / kubelet_volume_stats_capacity_bytes
  networkRx    : rate(container_network_receive_bytes_total[5m])
  networkTx    : rate(container_network_transmit_bytes_total[5m])

[클러스터 메타 - 별도 쿼리 (staleTime 5분)]
  namespaces   : group by (namespace) (kube_namespace_status_phase{phase="Active"})
  nodes        : group by (node) (kube_node_info)

--------------------------------------------------------------------------------
5. Pod 상태 판정 기준
--------------------------------------------------------------------------------

  error   : phase=Failed/Unknown, 재시작>=5회, CPU>=95%, MEM>=95%
  warning : phase=Pending, 재시작>=3회, CPU>=80%, MEM>=80%
  normal  : 그 외

Node 상태:
  error   : pod 중 error 존재 or CPU>=90% or MEM>=90%
  warning : pod 중 warning 존재 or CPU>=70% or MEM>=70%
  normal  : 그 외

7. 알려진 이슈 / 확인 필요 사항
--------------------------------------------------------------------------------

- CPU/MEM 사용률이 0%로 나올 경우
  → kube-prometheus-stack recording rule 존재 여부 확인
     node_namespace_pod_container:container_cpu_usage_seconds_total:sum_rate5m
     cluster:namespace:pod_cpu:active:kube_pod_container_resource_limits
     cluster:namespace:pod_memory:active:kube_pod_container_resource_limits

- Storage 사용률이 0%로 나올 경우
  → kubelet_volume_stats_used_bytes 메트릭 존재 여부 확인
  → volume이 없는 pod는 정상적으로 0% 표시됨

- Network 수치가 0으로 나올 경우
  → container_network_receive/transmit_bytes_total 메트릭 확인

- cluster 필터 기본값: "" (빈 문자열 = 전체)
 → 특정 cluster만 보려면 URL 파라미터: ?cluster=upm-ems

[기능 1] Pod 상세 패널 - PV 사용률 상세 조회
--------------------------------------------------------------------------------

  개요:
    Pod 클릭 시 해당 Pod에 마운트된 PVC별 스토리지 사용 현황을
    Grafana "Kubernetes / Persistent Volumes" 대시보드 수준으로 표시한다.

  현재 구현과의 차이:
    - 현재: storageUsage (used/capacity 비율) 단일 수치만 표시
    - 목표: PVC별 Used/Free bytes + 사용률(%) + inode 사용량 표시

  쿼리 방식:
    kubelet_volume_stats_* 메트릭에 pod label이 포함되어 있으므로
    namespace + pod 이름으로 직접 조회 가능. 별도 PVC 변수 불필요.

    Used bytes   : kubelet_volume_stats_capacity_bytes{namespace, pod}
                   - kubelet_volume_stats_available_bytes{namespace, pod}
    Free bytes   : kubelet_volume_stats_available_bytes{namespace, pod}
    Used %       : (capacity - available) / capacity * 100
    inode used   : kubelet_volume_stats_inodes_used{namespace, pod}
    inode free   : kubelet_volume_stats_inodes{namespace, pod}
                   - kubelet_volume_stats_inodes_used{namespace, pod}
    inode %      : inodes_used / inodes * 100

  구현 방식: on-demand 조회 (Pod 클릭 시 별도 hook 호출)
    - 배치 쿼리에 포함하지 않고 selectedPod 세팅 시 별도 쿼리 실행
    - 이유: Pod 미선택 상태에서 불필요한 메트릭 조회 방지, PVC 복수 표시 용이

  신규/수정 파일:
    core/frontend/src/features/home-dashboard/hooks/use-pod-volume-detail.ts (신규)
      - usePodVolumeDetail(pod, datasourceName) hook
      - pod 선택 시 4개 메트릭 on-demand 조회
      - PVC별 { pvcName, usedBytes, freeBytes, usedPercent,
               inodesUsed, inodesFree, inodesPercent } 반환

    core/frontend/src/features/home-dashboard/components/PodDetailPanel.tsx (수정)
      - volumeDetails prop 추가
      - Storage UsageRow → PVC별 상세 표시로 확장
      - bytes 단위 자동 변환 (B/KB/MB/GB)
      - inode 사용률 표시 추가

    core/frontend/src/routes/home-upm/page.tsx (수정)
      - usePodVolumeDetail 호출 후 PodDetailPanel에 전달

  확인 사항:
    - kubelet_volume_stats_used_bytes 메트릭 존재 여부 확인
      (없을 경우 kubelet_volume_stats_available_bytes 기반으로 계산)
    - volume 없는 pod는 PV 섹션 미표시 처리

[기능 2] Pod 상세 패널 - Force Delete 버튼
--------------------------------------------------------------------------------

  개요:
    Pod 상세 패널 우측 상단의 '대시보드' 버튼을 'Force Delete' 버튼으로 교체.
    클릭 시 패스워드 확인 다이얼로그를 거친 후 Pod를 강제 삭제한다.

  UI 흐름:
    1) Force Delete 버튼 클릭
    2) 확인 다이얼로그 표시 (shadcn/ui Dialog 컴포넌트)
       - 삭제 대상 pod 이름 / namespace 안내 문구
       - 패스워드 입력 필드 (type="password")
       - 확인 / 취소 버튼
    3) 확인 클릭 → 패스워드 검증 API 호출
       - 성공: pod force delete API 호출 → 패널 닫힘 + 토스트 알림

11-1. 목적 및 설계 방침
--------------------------------------------------------------------------------

  목적:
    현재 core에 고정 배선된 home-upm 화면을 extension으로 분리하여,
    프로젝트(UPM, CATV 등)마다 독립적인 홈 화면을 가질 수 있도록 한다.

  설계 방침 (login-extension 선례 기반):
    - meta/configs/{mode}.json에 "home-extension" 필드(선택)를 추가한다.
    - 실제 extension 로딩/빌드 포함 여부는 기존 "extensions" 배열이 단일 기준이다.
    - home-extension은 extensions에 포함된 extension 중 홈 화면으로 사용할 대상을 지정한다.
    - home-extension이 지정된 경우 해당 값은 extensions 배열에도 반드시 포함되어야 한다.
      예: "home-extension": "home-upm", "extensions": ["alarm", "log", "home-upm"]
    - home-path 필드는 선택 override로만 둔다.
      미지정 시 HOME_PATH는 "/extensions/{home-extension}"으로 자동 생성한다.
    - home-extension이 없는 경우 core 기존 대시보드 홈(/home)으로 fallback한다.
    - 홈 경로는 빌드 시점에 meta/generated/frontend/site-config.ts로 생성하여
      런타임 하드코딩을 제거한다.
    - 주의: /home 라우트 자체는 기존 HomePage를 렌더링해야 한다.
      HOME_PATH가 '/home'인 경우 /home → /home self-redirect 루프가 발생할 수 있으므로
      / 라우트만 HOME_PATH로 redirect한다.

  참고:
    - login-extension도 동일한 패턴. 모든 config(upm/catv/default)에 명시되어 있음.
    - home-extension 없는 config는 기존 대시보드 홈이 자연스러운 기본값이다.

--------------------------------------------------------------------------------
12-1. 목적
--------------------------------------------------------------------------------

  Pod 상세 패널의 Storage (Volume) 항목에
  해당 Pod에 마운트된 PVC별 스토리지 사용 현황을 상세 표시한다.

  현재:
    Storage (Volume)  ████████░░░░  0%  (단일 수치, 항상 0% 문제)

  목표:
    Storage (Volume)
    ┌────────────────────────────────────────────────┐
    │ pgdata-ofcs-postgres-0                         │
    │  Space  ████████░░  80%   8.0 GB / 10.0 GB    │
    ├────────────────────────────────────────────────┤
    │ logdata-ofcs-app-0                             │
    │  Space  ███░░░░░░░  30%   1.5 GB / 5.0 GB     │
    └────────────────────────────────────────────────┘
    PVC 없는 pod → "No Volumes" 표시

  참고:
    섹션 10 [기능 1]의 설계를 기반으로 하며,
    Grafana "Kubernetes / Persistent Volumes" 대시보드의 실제 PromQL을
    UPM Pod 상세 패널에 맞게 변환한 쿼리를 아래에 명세한다.

--------------------------------------------------------------------------------
12-2. Grafana 대비 변환 포인트
--------------------------------------------------------------------------------

  Grafana 대시보드:
    namespace + persistentvolumeclaim(PVC 이름)을 변수로 직접 선택한다.

  UPM Pod 상세 패널:
    Pod 클릭 시 namespace + pod 이름을 이미 알고 있다.
    kubelet_volume_stats_* 메트릭에 pod 레이블이 포함되므로
    PVC 이름 없이 namespace + pod 조합으로 해당 Pod의 모든 PVC를 한 번에 조회한다.
    조회 결과에 persistentvolumeclaim 레이블이 남아 있어 PVC별 그룹핑이 가능하다.

  topk(1, ...) 패턴 유지:
    동일 PVC 메트릭이 복수 kubelet 인스턴스에서 중복 수집될 수 있으므로
    Grafana와 동일하게 topk(1, ...)로 중복을 제거한다.

  job / metrics_path 필터 포함:
    job="kubelet", metrics_path="/metrics" 조건을 쿼리에 포함한다.
    (metrics_path="/metrics/cadvisor"와 구분하기 위함)

--------------------------------------------------------------------------------
12-3. 적용 PromQL (pod 기준, 2개 쿼리 배치 호출)
--------------------------------------------------------------------------------

  배경:
    kubelet_volume_stats_* 메트릭은 kubelet이 볼륨 단위로 수집하므로
    pod 레이블이 존재하지 않는다. namespace, persistentvolumeclaim 레이블만 있음.
    pod → PVC 매핑은 kube-state-metrics의
    kube_pod_spec_volumes_persistentvolumeclaims_info 로 연결한다.

  join 패턴:
    max by (namespace, persistentvolumeclaim) (kubelet_volume_stats_*{...})
    * on(namespace, persistentvolumeclaim) group_left()
    max by (namespace, persistentvolumeclaim) (
      kube_pod_spec_volumes_persistentvolumeclaims_info{namespace="$namespace", pod="$pod"}
    )

  주의:
    kube_pod_spec_volumes_persistentvolumeclaims_info 에는 uid, volume 등 extra 레이블이
    있어 동일 (namespace, pvc) 키에 여러 series가 생성될 수 있다.
    join 시 "multiple matches" 오류를 방지하기 위해 양쪽 모두
    max by (namespace, persistentvolumeclaim) 로 집계하여 1:1 join 을 보장한다.
    (topk + sum without 방식은 이 문제를 해결하지 못함)

  [1] capacityBytes — PVC 전체 용량 (bytes)
    max by (namespace, persistentvolumeclaim) (
      kubelet_volume_stats_capacity_bytes{
        job="kubelet", metrics_path="/metrics", namespace="$namespace"
      }
    )
    * on(namespace, persistentvolumeclaim) group_left()
    max by (namespace, persistentvolumeclaim) (
      kube_pod_spec_volumes_persistentvolumeclaims_info{
        namespace="$namespace", pod="$pod"
      }
    )

  [2] availableBytes — PVC 여유 공간 (bytes)
    max by (namespace, persistentvolumeclaim) (
      kubelet_volume_stats_available_bytes{
        job="kubelet", metrics_path="/metrics", namespace="$namespace"
      }
    )
    * on(namespace, persistentvolumeclaim) group_left()
    max by (namespace, persistentvolumeclaim) (
      kube_pod_spec_volumes_persistentvolumeclaims_info{
        namespace="$namespace", pod="$pod"
      }
    )

  usedBytes   = capacityBytes - availableBytes  (JS 계산)
  freeBytes   = availableBytes                  (JS 계산)
  usedPercent = usedBytes / capacityBytes * 100 (JS 계산)

--------------------------------------------------------------------------------
13. Pod 상세 패널 - Network 표시 개선
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
13-1. 목적
--------------------------------------------------------------------------------

  현재 Network 섹션은 Rx/Tx 수치만 나열되어 트래픽 방향과 비율을 직관적으로
  파악하기 어렵다. 상대적 바 차트를 추가하여 시각적으로 개선한다.

  현재:
    Network
    ↓ 123.0 KB/s  ↑ 15.7 KB/s

  변경 후:
    Network                              합계 138.7 KB/s
    ↓ 수신   ████████████░░░░  123.0 KB/s
    ↑ 송신   ██░░░░░░░░░░░░░░   15.7 KB/s

--------------------------------------------------------------------------------
13-2. 바 차트 스케일 방식
--------------------------------------------------------------------------------

  max(rxBps, txBps)를 100%로 잡고 각 바의 너비를 상대적으로 계산한다.
  외부 기준값(네트워크 대역폭 한도 등) 없이 두 값의 상대 비율만 표현한다.

  예시:
    rxBps = 123.0 KB/s, txBps = 15.7 KB/s
    max = 123.0 → rx 바 100%, tx 바 12.8%

  rxBps = txBps = 0 인 경우:
    바 없이 "0 B/s" 수치만 표시한다.

--------------------------------------------------------------------------------
13-3. 색상 및 레이블
--------------------------------------------------------------------------------

  ↓ 수신 (Rx):  cyan   (text-cyan-400   / bg-cyan-500)
  ↑ 송신 (Tx):  green  (text-green-400  / bg-green-500)

  합계 표시:
    우측 상단에 작은 글씨로 "합계 {rx+tx}" 표시.
    단위는 Rx/Tx와 동일한 자동 단위 변환 적용.

  단위 변환 (기존 로직 재사용):
    < 1 KB  → B/s
    < 1 MB  → KB/s
    < 1 GB  → MB/s
    그 이상 → GB/s

--------------------------------------------------------------------------------
13-4. 구현 명세
--------------------------------------------------------------------------------

  [수정 파일]
    core/frontend/src/features/home-dashboard/components/PodDetailPanel.tsx

      변경 전 Network 섹션:
        <UsageRow label="Network" ... />  (단순 수치 표시)

      변경 후:

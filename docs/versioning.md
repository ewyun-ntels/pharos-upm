# 릴리즈 버전 규칙 (Versioning Policy)

이 문서는 프로젝트의 릴리즈 버전 관리 규칙을 정의합니다.  
팀원과 CI/CD 워크플로우가 일관되게 참조할 수 있도록 작성되었습니다.

---

## 1. 버전 기본 원칙

- **SemVer(주.부.패치)** 기반 버전 관리
    - 예: `v1.2.3` → Major: 1, Minor: 2, Patch: 3
- 버전 태그에 따라 **모드**를 구분
    1. **기본 모드**: 일반 릴리즈 및 기본 베타
    2. **사이트 모드**: 특정 사이트 관련 릴리즈
    3. **사이트 베타**: 특정 사이트 관련 베타 릴리즈

---

## 2. 태그 패턴

| 패턴                    | 설명              | 예제                                             |
|-----------------------|-----------------|------------------------------------------------|
| `v*.*.*`              | 기본 모드 정식 릴리즈    | `v1.2.3`                                       |
| `v*.*.*-default-beta` | 기본 모드 베타 릴리즈    | `v1.2.3-default-beta`, `v1.2.3-default-beta.1` |
| `v*.*.*-*`            | 사이트 모드 정식 릴리즈   | `v1.2.3-siteA`                                 |
| `v*.*.*-*-beta`       | 사이트 모드 베타 릴리즈   | `v1.2.3-siteA-beta`                            |
| `v*.*.*-*-beta.*`     | 사이트 모드 베타 세부 버전 | `v1.2.3-siteA-beta.1`                          |

> 💡 **기본 모드**는 특별한 사이트 지정 없이 일반 릴리즈를 의미합니다.  
> 정식 릴리즈: `v*.*.*`  
> 베타 릴리즈: `v*.*.*-default-beta`

## 3. 참고

- 모든 릴리즈 태그는 GitHub Actions `release.yml` 워크플로우와 연동
- CI/CD에서 자동화 스크립트가 태그 형식에 따라 릴리즈 아티팩트 생성
- 버전 규칙 변경 시 반드시 문서 갱신 및 워크플로우 검증 필요
